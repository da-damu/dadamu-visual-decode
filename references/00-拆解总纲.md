# 拆解总纲

这份文件管方法，不管具体术语。具体术语在 `01`–`04`，需求翻译在 `05`，术语库在 `06`。

---

## 一、这个 skill 要补的缺口

自媒体创作者常见的状态：

- 看得出两个作品不一样，但说不清差在哪
- 知道自己喜欢哪一个，但只能说「这个更高级」
- 给 AI 的描述只有「要电影感、要高级、要有氛围」
- 拿到 AI 的结果觉得不对，但改不动，因为不知道该改哪个参数

**缺口不在审美，在词汇和参数。**

审美是「我更喜欢哪一个」。词汇是「它用了什么手法」。参数是「我怎么让它再靠近一点」。

拆解就是把这三件事接起来：

```
感觉 → 可观察的现象 → 专业术语 → 可复现的参数 → 可验收的需求
```

---

## 二、四层翻译

每一次拆解，至少走完这四层。

| 层 | 问题 | 输出 | 不合格的样子 |
| --- | --- | --- | --- |
| 现象 | 我在画面里看到了什么？ | 时间码、区域、具体元素 | 「很有氛围」 |
| 术语 | 这个现象叫什么？ | 中文名 + 英文名 + 一句话定义 | 只给英文缩写，不解释 |
| 参数 | 怎么做到的？ | 设置、范围、步骤、工具 | 「调一下色」 |
| 需求 | 我怎么让别人 / AI 做出来？ | 一句能直接粘贴的话 + 禁止项 + 验收 | 「要那种感觉」 |

**四层缺一层，用户就还得自己补。** 补不上的地方，就是下一次沟通翻车的地方。

## 三、三种深度

### 快拆（300–500 字）

用在：用户只问「这是什么风格」「这个效果叫什么」。

给：

1. 一句话判断
2. 3 个术语（每个一行：证据 + 参数）
3. 3 个今天能试的动作

**不做**：逐镜头、完整配方、需求卡三版。

### 标准拆（默认，1000–1800 字）

用在：用户发来作品，想看懂 + 想复现 + 想提需求。

给：

1. 一句话判断
2. 五层拆解（L1–L5）
3. 术语卡 ×5–7
4. 复现配方（分成本档）
5. 需求翻译卡（三版）
6. 下一步学什么
7. 置信度与不可见项

### 深拆（2500 字以上，写文件）

用在：用户要系统学、要做风格复刻、要拿去做团队 brief。

在标准拆基础上加：

- 逐镜头 / 逐屏表
- 参数测量（色板、字号比例、间距、圆角、动效时长）
- 与 2–3 个参照作品对比
- 3 周学习路径
- 术语库更新

**深度由用户的目的决定，不由作品长度决定。** 一个 15 秒视频也可以深拆；一个 3 分钟视频也可能只需要快拆。

## 四、五层拆解法

### L1 · 整体印象

先不看细节，回答六个坐标：

| 坐标 | 两端 | 你看到的位置 |
| --- | --- | --- |
| 温度 | 冷 ←→ 暖 | 画面整体偏蓝青还是偏黄橙 |
| 密度 | 简 ←→ 繁 | 留白多还是元素满 |
| 动静 | 静 ←→ 动 | 固定镜头 / 慢节奏，还是手持 / 快切 |
| 虚实 | 实 ←→ 虚 | 清晰记录，还是风格化、抽象、合成 |
| 新旧 | 旧 ←→ 新 | 胶片、复古、印刷感，还是 3D、霓虹、未来感 |
| 轻重 | 轻 ←→ 厚 | 轻快、透明、薄，还是厚重、暗、压迫 |

再补三句：

- **它是什么**：广告 / vlog / 知识口播 / 产品页 / 品牌官网 / 海报 / 封面
- **给谁看**：年龄段、消费场景、平台
- **想让你产生什么感受**：安静、紧张、贵、亲切、专业、热闹、孤独

**L1 不写术语，写判断。** 术语从 L3 开始。

### L2 · 结构

不同载体的结构问题不一样。

**视频：**

- 前 3 秒给了什么？人物、结果、冲突、还是环境？
- 镜头序列是「建立 → 细节 → 反应 → 落点」，还是「快切堆信息」？
- 平均镜长多少？最长镜头在哪？最短镜头在哪？
- 转场是硬切为主，还是叠化 / 遮罩 / 甩镜？
- 声音有没有参与结构（J-cut、声音桥、静音）？

**网页 / App：**

- 首屏第一眼看到什么？标题、产品图、视频、还是数据？
- 导航在哪？几个层级？用户下一步去哪？
- 网格是 12 栏、卡片流、还是全屏分段？
- 信息层级靠字号、颜色、间距、还是位置？
- 有没有重复出现的组件模式？

**图片 / 平面：**

- 视觉重心在哪？第一眼、第二眼分别落在哪？
- 用了什么构图：三分、中心、对称、对角线、框架、引导线？
- 主体和背景是什么关系：分离、融合、遮挡、重复？
- 阅读动线是 Z 型、F 型、还是从中心向外？

### L3 · 元素

逐项过一遍，不要漏：

| 类别 | 看什么 |
| --- | --- |
| 色彩 | 主色、辅助色、点缀色；饱和度、明度、对比度；冷暖；色板数量 |
| 光线 | 光源方向、软硬、光比；主光 / 辅光 / 轮廓光；自然光 / 人造光 |
| 字体 | 衬线 / 无衬线 / 等宽 / 手写；字重、字号、行高、字距；中英混排 |
| 图形 | 几何 / 有机 / 手绘 / 像素 / 3D；线条粗细；圆角 / 直角 |
| 材质 | 金属、玻璃、纸张、布料、塑料、水、烟、颗粒、噪点 |
| 人物 | 景别、姿态、视线、服装、妆发、表演强度 |
| 道具 | 品牌露出、年代感、颜色是否呼应主色 |
| 组件 | 按钮、卡片、输入框、导航、标签、图标、空状态 |
| 图片 | 产品图 / 场景图 / 生活方式图；抠图 / 蒙版 / 圆角 / 阴影 |

### L4 · 动态

| 类别 | 看什么 |
| --- | --- |
| 运镜 | 固定、摇、移、推、拉、跟、升降、环绕、手持、变焦、推拉变焦 |
| 剪辑 | 硬切、跳切、匹配剪辑、交叉剪辑、蒙太奇、卡点、变速 |
| 转场 | 切、叠化、淡入淡出、划像、遮罩、形状、甩镜、遮挡、故障 |
| 动效 | 淡入、位移、缩放、旋转、弹簧、错峰、视差、滚动触发 |
| 缓动 | 线性、缓入、缓出、缓入缓出、弹簧、回弹 |
| 节奏 | 平均镜长、剪辑密度、快慢对比、停顿 |
| 声音 | 对白、旁白、环境声、音效、配乐、静音、声音桥 |

### L5 · 技术

| 类别 | 看什么 | 置信度 |
| --- | --- | --- |
| 画幅 | 16:9 / 9:16 / 4:3 / 2.35:1 / 1:1 / 4:5 | 高 |
| 帧率 | 24 / 25 / 30 / 50 / 60；有没有升格 | 高（看元数据） |
| 分辨率 | 1080p / 2K / 4K | 高（看元数据） |
| 镜头 | 广角 / 标准 / 长焦；畸变、压缩感 | 中 |
| 景深 | 浅 / 深；光斑形状 | 高 |
| 灯光 | 硬 / 软；方向；光比 | 中 |
| 调色 | 一级 / 二级；LUT；颗粒；光晕 | 中 |
| 软件 | 剪辑、合成、调色、动效工具 | 低（除非看工程） |
| 网页实现 | CSS Grid / Flex / 变量 / 动画 / 毛玻璃 | 高（看源码） |

**L5 的作用是给复现配方提供参数，不是炫技。** 看不出来的就写「无法确认」。

## 五、证据规则

### 每个术语都要有「指得到」的证据

合格的证据：

- 时间码：00:08、00:12–00:15
- 画面区域：首屏、左上角、人物背后、卡片底部
- 具体元素：招牌文字、发丝边缘、按钮圆角、滚动条
- 代码位置：`style.css` 第 42 行、`site-probe.json` 的 `fonts`

不合格的证据：

- 「整体感觉」
- 「看起来很贵」
- 「有电影感」
- 「应该是大光圈」

### 证据不足时的三种处理

1. **降级为推测**：写「看起来像」，给验证方法
2. **删掉**：这个术语对当前问题不重要
3. **换一个能确认的术语**：从「具体镜头型号」换成「长焦压缩感」

### 不要用术语解释术语

反例：

> 「这里用了伦勃朗光，所以有明暗对照的效果。」

正例：

> 「人物脸的一侧亮、另一侧暗，颧骨下方有一块三角形亮区——这是伦勃朗光。它让脸看起来更立体，也更有戏剧性。」

## 六、置信度

| 级别 | 判断依据 | 写法 |
| --- | --- | --- |
| 高 | 直接可见、可测量、可看元数据 / 源码 | 「这是硬切」「这是 9:16」「这是 CSS Grid」 |
| 中 | 多条线索交叉，但存在替代解释 | 「看起来像 35–50mm」「大概率是柔光」 |
| 低 | 被压缩、遮挡、后期掩盖，或需要工程文件 | 「无法从成片确认具体镜头 / 插件 / 字体」 |

**低置信度不是缺点，装成高置信度才是。**

用户要的是「知道下一步怎么验证」，不是「你猜得准不准」。

## 七、常见误判

### 1. 把风格当技巧

「电影感」不是某一个滤镜。它通常是多项选择的组合：画幅、帧率、景深、灯光、调色、运镜、剪辑节奏。

**看到「电影感」，要拆成至少 4 个具体手段。**

### 2. 把结果当原因

「高级」是结果，不是原因。原因可能是：

- 低饱和 + 低对比
- 大量留白
- 字体克制（少字重、少字号层级）
- 材质统一（没有互相打架的纹理）
- 光源方向明确
- 颜色数量少

**要把形容词还原成可观察的变量。**

### 3. 把平台压缩当创作选择

画质糊、色彩断层、暗部死黑、锐化过度，可能是上传压缩造成的，不一定是作者的选择。

**看到这些，先问：是原片就这样，还是平台压的？**

### 4. 把 AI 生成痕迹当风格

过度光滑的皮肤、错误的手、重复的纹理、不对称的光影、糊掉的文字——这些是生成痕迹，不是风格。

**可以说「看起来像 AI 生成」，但要给证据，不要武断。**

### 5. 把术语多当专业

30 个术语堆在一起，用户一个也记不住。

**一次 5–7 个，能用在下次拍摄 / 剪辑 / 提需求里的，才算有效。**

### 6. 把一段当整体

一个视频里可能混了三种风格：开头是快切广告，中间是口播，结尾是产品特写。

**先分段，再判断整体。** 不要拿一个转场定义整条片子。

### 7. 把参考作品的整体当目标

用户说「我要这种风格」，可能只是喜欢其中一个镜头、一个配色、一个字体。

**先问「你具体喜欢哪一段 / 哪一个元素」，再拆。**

### 8. 把「像」当成「是」

“像胶片”不等于“是胶片”。胶片模拟、LUT、颗粒插件都能做出相似效果。

**写「胶片感 / 胶片模拟」，不要写「用胶片拍的」，除非有证据。**

## 八、观察顺序

### 视频

1. **静音看一遍**：只看画面，记整体印象和三个最强特征
2. **闭眼听一遍**：只听声音，记节奏、信息密度、情绪
3. **看联系表**：建立镜头序列，标出重复出现的构图 / 色彩 / 机位
4. **逐帧看关键段**：只挑 6–12 个关键帧，不要每帧都看
5. **看元数据**：时长、帧率、分辨率、码率、音轨
6. **回看整体**：确认术语没有把主线拆碎

### 网页 / App

1. **首屏 3 秒**：第一眼看到什么？下一步想点哪？
2. **滚动一遍**：页面分几段？每段的任务是什么？
3. **三档宽度**：桌面、平板、手机，看布局怎么变
4. **看组件**：按钮、卡片、导航、输入框的尺寸和状态
5. **看动效**：进入、悬停、滚动、页面转场
6. **看源码 / 计算样式**：字体、颜色、间距、圆角、阴影、断点

### 图片 / 平面

1. **眯眼看**：只看大色块和视觉重心
2. **正常看**：主体、背景、文字、图形的关系
3. **分区看**：左上、右上、左下、右下、中心
4. **看边缘**：主体边缘、文字边缘、光影过渡
5. **看细节**：材质、颗粒、噪点、印刷纹理
6. **看色板**：主色、辅助色、点缀色各几个

## 九、拆解稿结构

标准拆解按这个顺序写，别一上来就术语卡：

```markdown
# <作品名> 拆解

## 一句话判断
...

## 整体印象（L1）
...

## 结构（L2）
...

## 元素与动态（L3 + L4）
...

## 术语卡
### 01 ...
### 02 ...

## 复现配方
### 最省力的 20%
### 完整配方
### 成本分档

## 需求翻译卡
### 对 AI
### 对设计师 / 剪辑师
### 对自己

## 下一步学什么

## 置信度与不可见项
```

**为什么先整体：** 用户要先知道「这是什么」，才装得下术语。先给 20 个词，用户只会觉得被上课。

## 十、语言自检

交付前逐条过。命中不是必须改，先问「删掉它，意思有没有损失」。

### 用词

- [ ] 没有「赋能、助力、打造、构建、实现、聚焦、落地、沉淀、拉通、抓手」
- [ ] 没有「关键、至关重要、里程碑、标志性、具有深远意义、扮演着重要角色」
- [ ] 没有「底层逻辑、第一性原理、重新定义、范式、心智、颗粒度、对齐」
- [ ] 没有用术语替代解释

### 结构

- [ ] 没有段段下结论
- [ ] 没有连续三段用同一个句式
- [ ] 没有三项排比（「更…、更…、更…」）
- [ ] 没有「第一点 / 其次 / 最后」这种无信息量的小标题
- [ ] 没有「挑战与展望」式结尾

### 表达

- [ ] 没有「大家好，今天分享一个」
- [ ] 没有「值得注意的是」「本质上」「真正重要的是」「说到底」
- [ ] 没有「不是 X，而是 Y」连续出现两次以上
- [ ] 没有「研究表明 / 业内普遍认为」而不给具体来源
- [ ] 没有把情绪写成身体表演（「心跳加速」「手心冒汗」）

### 逻辑

- [ ] 每个判断都有证据
- [ ] 每个术语都有参数或做法
- [ ] 不确定的地方标了置信度
- [ ] 没有为了去味删掉事实、数字、条件、限定

**这一节只去味，不改立意、事实、判断。** 信息守恒优先。

## 十一、外部知识怎么用

拆解主要靠画面，不靠百科。外部知识只在三种情况下出现：

1. **解释术语**：这个流派大致是什么、常见特征是什么
2. **给搜索关键词**：用户想继续学，去哪里找
3. **做参照**：这件作品和另一个已知作品 / 流派像在哪

**规则：**

- 不确定的年代、人名、作品名，不写
- 写「常见说法」，不写「公认」「研究表明」
- 不把外部知识当画面证据
- 不为了显得专业，硬扯流派

## 十二、输出长度

| 深度 | 字数 | 术语数 | 配方步骤 | 需求卡 |
| --- | --- | --- | --- | --- |
| 快拆 | 300–500 | 3 | 3 条动作 | 不给完整卡 |
| 标准拆 | 1000–1800 | 5–7 | 5–10 步 | 三版 |
| 深拆 | 2500+ | 7（多出来的进附录术语表） | 10–15 步 | 三版 + 验收表 |

**超过 1800 字还不是深拆，通常是术语堆多了。** 先删到 7 个，再决定要不要写文件。
